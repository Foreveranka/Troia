# Troia · TR Mock Anchor integration

## What is implemented

- `/`: dedicated project introduction.
- Extension popup → **Bank transfers**: persistent extension panel with Freighter wallet, account preparation, Circle testnet USDC trustline, SEP-10 authentication, SEP-38 quotes, SEP-6 deposits/withdrawals, history and status polling.
- `/wallet`: narrow wallet approval helper only. It is opened by the extension for Freighter connection/signatures.
- `/app`: now shows the introduction; there is no separate web dashboard.
- `/store`: existing card checkout demo, kept separate from bank transfers.
- Bank settlement is simulated. Stellar USDC transfers are real **testnet** transactions. This is not a BiLira production integration.
- Backend defaults to `TROIA_FUNDING_MODE=manual`: confirmed payouts are booked exactly once, with no automatic mint/replenishment. Drift checks remain enabled.

## Run locally

```sh
pnpm install --frozen-lockfile
pnpm build
cd app/storefront
npm ci
npm run dev -- --host 127.0.0.1 --port 5174
```

Keep http://127.0.0.1:5174 running for the wallet helper. Build and load the extension:

```sh
cd app/extension
npm ci
npm run build
```

In Chrome, open `chrome://extensions`, enable Developer mode, choose **Load unpacked** and select `app/extension/dist`. Pin Troia and click **Bank transfers**. The card payment panel also links to bank transfers. On browsers without side-panel support, Troia opens its packaged extension page in a tab.

Connect Freighter on Testnet. Only approval opens a companion web tab; amounts, quotes and history remain inside Troia. Prepare wallet if prompted. Request a TRY deposit quote, confirm, then simulate the bank transfer. Withdraw test USDC by approving the destination and memo in Freighter.

`WALLET_BRIDGE_URL` in `app/extension/src/lib/config.ts` is the single configured helper URL. Set it to the deployed HTTPS `/wallet` URL before distributing the extension, then rebuild. Local preview uses port 5174 so the existing storefront on port 5173 can keep running. No other running project was restarted.

The packaged extension adds only the configured helper, anchor, Horizon and Friendbot host permissions. It contains its own JS/CSS and no remote script or font dependency. The helper relay accepts replies only from the matching tab, top-level frame, exact origin/path and random request ID. Credentials remain in Freighter; the extension receives approved signatures.

## Current deployment

The new pool, dedicated operator, recipient trustline, public wallet helper and downloadable extension are implemented. See [DEPLOYMENTS.md](DEPLOYMENTS.md). The helper URL comes from `walletBridgeUrl` in the deployment record and is generated by `scripts/wire-apps.mjs`.

Pool funding is manual and separate from customer bank transfers. Circle's official faucet supplied initial test USDC because the anchor's SEP-6 service currently stalls at `pending_anchor`. No substitute USDC was minted. A fresh end-to-end off-ramp test awaits recovery.

Later top-ups require the verified transfer bookkeeping tool described in [JURY-READINESS.md](JURY-READINESS.md). Never reset journals or suppress drift checks.

## Recovery and limitations

After a withdrawal timeout, refresh history and inspect the transaction; do not pay twice. A browser-local marker is stored after signing and before broadcast. It is not a cross-device lock. Production requires durable cross-device recovery and comprehensive security review.

The UI checks discovered origin/network/asset, verifies SEP-10, checks quote expiry and wallet-signed transaction contents, and compares amounts using integer units. Firm quotes use `deposit-exchange` and `withdraw-exchange`, because ordinary endpoints can ignore the quote ID. These checks do not constitute a full audit.
